# WP-N: economy (mana)

**Owns:** `crates/tak-sim/src/economy.rs` (and an `economy/` submodule folder), `docs/economy.md`.
**Lane API:** `economy::drain(world, player, want) -> granted` (construction and combat call it; keep the signature), `economy::tick`. Expose read accessors (player mana, income, storage) for tools and the future UI.

## Starting point (on main)
- Kingdoms has one resource, mana. Keys found by WP-H: units `buildcost`, `maxmana`, `manarechargerate`, `mogriumincome`, `mogriumstorage`, `economybonus`; weapons `manapershot`; features `sacredsite` (on `*Mana0N` lodestone sites) and `energy`; OTA placed units `manapercentage`. Read `docs/content.md` and the census docs.
- Believed (handoff): mana is generated by the monarch and by buildings placed on lodestones. Each unit with `maxmana` also has its own pool for spells.
- The install has `readme.htm` and `Docs/*.txt` (unit notes) that may state rules. You may use WebSearch/WebFetch to read community documentation of TA:K's economy rules (read only; cite sources in the doc).

## Build
1. Work out the actual rules from the data and documentation, before coding: what generates income (monarch, lodestone buildings, `mogriumincome`?), storage caps (`mogriumstorage`?), what `economybonus` and `energy` do, whether build costs are paid up front or drained over build time (TA drains over time; check Kingdoms). Write them in `docs/economy.md` with confidence tags.
2. Per-player mana pool in fixed point (use `WideFx` if values exceed `Fx`), income per tick, storage cap.
3. `drain`: deterministic allocation when several consumers ask in one tick (TA scales everyone's progress proportionally when short; implement that unless Kingdoms differs), in slot order.
4. Per-unit mana pools (`maxmana`, `manarechargerate`) for spellcasters, with an API combat can spend from.
5. Starting mana from the map/OTA or a match setting.
6. A headless report: `tak-headless run ... --economy-report` (or similar) printing per-player mana over time.

## Done when
- With only a monarch, income per second matches the rule in `docs/economy.md`; with lodestone buildings (spawned directly in a test), income rises as documented.
- `drain` unit tests cover full grant, partial grant and proportional sharing.
- Cross-process determinism test; all existing tests pass; no floats.
