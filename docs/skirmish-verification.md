# Controller-first skirmish verification

Scope: Adamantine Gate, Aramon/Zhon, seed 1, built-in training or passive
opposition. Verification performed on a Linux cloud desktop with software Vulkan;
no physical-controller acceptance is claimed. No retail assets, screenshots,
checkpoints, or extracted data are included in this source document.

## Automated checks

- Core workspace: 623 passed, 0 failed, 2 ignored doctest examples, both without
  installed data and with a valid owned installation. Missing-data early returns
  in the first run are not counted as owned-content verification.
- Client library and existing integration targets: 160 passed with owned data
  (118 library, including 18 UI/adapter tests, plus 42 integration tests).
- New skirmish integration target: 10 passed with owned data. Without an install,
  its three `installed_*` cases return early with explicit skip messages.
- Separately executed the ignored long owned-result diagnostic: 1 passed,
  exercising four actual ordinary gameplay outcomes and result save/replay hashes.
- Both workspaces pass formatting and all-target clippy with warnings denied.
  The fail-closed third-party-notice collector has 23 passing tests.

The UI tests drive actual Bevy gamepad button/axis resources through the production
adapter, including held input, default-Cancel confirmations, modal exclusivity,
startup, result, and replacement transitions. They are simulated-pad tests, not
physical controller tests and not a fully rendered GUI pad session.

## Ordinary installed-content gameplay

The diagnostic submits normal build, production and attack commands; it does not
spawn armies, alter health/resources, inject a result or bypass paid construction.
Against an idle human, Aramon's training army wins at tick 7221 and Zhon's at tick
39532. Scripted local-player production against passive opposition wins at tick
6766 for Aramon and 33396 for Zhon. These are reproducibility observations for the
validated install and seed, not balance targets or human skill benchmarks.

Zhon initially stalled because its only direct ordinary monarch troop was beyond
normal storage. Resolving an affordable troop through the real mobile-builder
menu edge fixed the loop. Existing planner placement and paid construction already
supported that path; only producer validation needed a narrow additive extension.
Asset-free tests cover it and preserve raw replay and save/resume equivalence.

## Native GUI observations

Using mouse and keyboard on the rendered client:

- Startup setup stayed paused on Escape; faction/opponent choice and launch worked.
- A running-match setup paused the world. Default-Cancel replacement confirmation
  and cancellation preserved the running match.
- Zhon versus Aramon training reached a natural defeat after ordinary enemy
  construction/production/attacks. The actionable result menu appeared after the
  existing result-display delay; rematch restarted the selected configuration.
- Mouse drag selected the rematched monarch. Paid Beast Handler construction
  started while enemy units attacked, with the build order shown in the unit card.
- F10 saved that actual GUI session at tick 6981. The browser showed map, factions,
  elapsed simulation time and fingerprints; loading replay-verified it and left
  the match paused, with selection/camera/explored fog reset.
- Separately, the browser loaded an explicitly labeled near-victory checkpoint
  generated by the ordinary scripted-gameplay diagnostic. Resuming reached the
  real victory and actionable result menu. This checks rendered victory behavior,
  not a claim of a human-played victory from startup.

Still outside acceptance: physical-controller ergonomics, full original-game AI
parity, additional maps/factions, campaign transitions, and complete presentation
savestates. The checkpoint and input limitations in `client.md` continue to apply.
